Voice agents are latency products first

A voice agent can have the same model and tools as a text agent and still feel broken. Spoken interaction exposes every pause. The product either acknowledges the user quickly or the conversation starts to feel dead.

The useful architecture keeps wake detection hot, avoids reopening audio devices per turn, preloads speech dependencies, and streams feedback as soon as the system has something meaningful to say. The agent can still preserve full tool use; the voice layer is transport and timing, not a reduced brain.

Interruption is part of the interface

Real conversation includes correction. If the system keeps talking after the user has moved on, latency becomes a trust problem. Good voice UX needs fast stop behavior, quick end-of-utterance detection, and a clear thinking cue while the agent is working.
